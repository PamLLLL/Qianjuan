# 大纲生成规则

## 任务说明

根据已生成的基础设定、人物体系和世界观，生成一份结构完整的三幕式故事大纲。大纲应覆盖整个故事的主线走向、关键转折、副线规划和伏笔布局，为后续的分卷和章节生成提供可靠的顶层蓝图。

## 三幕结构规范

### 第一幕：开端（act_one）— 约占全书 25%

第一幕的核心使命是**建立故事世界并引爆核心冲突**。

- **日常建立**：用 1-3 个场景快速建立主角的日常生活状态，让读者了解主角是谁、生活在什么环境中、有什么性格特点
- **触发事件（inciting_incident）**：打破日常的关键事件。这个事件必须足够有力，迫使主角不得不做出反应和改变。明确写出具体是什么事件、如何发生的
- **抗拒与接受**：主角对改变的最初抗拒（体现人性的真实），以及最终接受挑战的内外因素
- **第一转折点（turning_point）**：标志主角正式踏上征程的节点事件。跨过这个点，主角没有退路，故事进入上升阶段
- **悬念钩子**：第一幕结尾应埋下一个强烈的悬念或揭示，驱动读者继续阅读

输出字段要求：
- `title`：第一幕的标题（如"命运之始"）
- `summary`：300字以上的第一幕概述
- `key_events`：3-5个关键事件列表，每个事件用一句话概括
- `turning_point`：第一转折点的详细描述（100字以上）

### 第二幕：发展（act_two）— 约占全书 50%

第二幕是故事的**主体部分**，承担着递进冲突、深化人物、编织支线的核心任务。

- **递进试炼**：主角面对一系列**难度递增**的挑战和对手。每次试炼应推动主角的成长，同时逐步揭示更大的冲突真相
- **中点逆转（midpoint）**：故事正中间的重大转折。它可以是：假胜利后的真相揭露、盟友的背叛、敌人身份的颠覆、主角自身的重大发现。中点逆转应彻底改变主角对局势的理解，提升故事的紧迫感
- **暗夜时刻**：中点逆转后，主角陷入最低谷——计划失败、重要的人离去、信念动摇。这是角色弧线中最关键的考验
- **第二转折点（turning_point）**：主角在最低谷中找到新的力量/真相/决心，做出关键决定，故事转向最终对决
- **副线交织**：主要副线应在第二幕中充分展开，并与主线产生交叉和影响

输出字段要求：
- `title`：第二幕的标题
- `summary`：500字以上的第二幕概述
- `key_events`：5-8个关键事件列表
- `midpoint`：中点逆转的详细描述（150字以上）
- `turning_point`：第二转折点的详细描述（100字以上）

### 第三幕：高潮与结局（act_three）— 约占全书 25%

第三幕是故事的**收束与升华**，所有线索汇聚于此。

- **最终对决准备**：主角集结力量、制定计划、做出牺牲。这个阶段应有仪式感和紧迫感
- **高潮（climax）**：整个故事最激烈、最关键的对决场景。高潮应同时解决**外部冲突**（击败敌人/完成任务）和**内部冲突**（角色的内心蜕变）。高潮的胜负应取决于角色在整个故事中的成长和积累，而非突然获得的外力
- **伏笔回收**：在高潮前后密集回收前文埋下的伏笔，给读者"原来如此"的满足感
- **结局（resolution）**：冲突解决后的新秩序。交代主要角色的最终命运，呼应故事开头（形成首尾对照），传递故事的核心主题
- **尾声余韵**：可选但推荐。用一个简短的场景暗示未来的可能性或留下回味

输出字段要求：
- `title`：第三幕的标题
- `summary`：300字以上的第三幕概述
- `climax`：高潮场景的详细描述（200字以上）
- `resolution`：结局的详细描述（150字以上）

## 副线规划（subplots）

- 规划 **2-4 条**副线
- 每条副线需包含：
  - `name`：副线名称（如"师徒暗线""兄弟决裂线"）
  - `description`：副线的起因、发展和结局概述（150字以上）
  - `related_characters`：涉及的角色姓名列表
- 副线的设计原则：
  - 每条副线应**服务于主线**——要么推动主线发展，要么深化主题，要么丰富角色塑造
  - 副线之间应有交叉和呼应，避免完全独立的平行叙事
  - 副线的结局应在主线高潮前后自然收束，不留未解决的悬空线

## 伏笔规划（foreshadowing）

- 规划 **3-6 个**伏笔
- 每个伏笔需包含：
  - `setup`：伏笔埋设的内容描述——在什么情境下以什么方式埋下
  - `payoff`：伏笔揭晓/回收的内容描述——如何在后续剧情中揭示真相
  - `setup_chapter`：预计埋设的章节范围（如"第3-5章"）
  - `payoff_chapter`：预计回收的章节范围（如"第35-40章"）
- 伏笔设计原则：
  - 伏笔的埋设应**自然不刻意**，读者第一次读到时不会觉得突兀，回收时才恍然大悟
  - 伏笔的跨度应有长有短——既有短线伏笔（5-10章内回收），也有贯穿全书的长线伏笔
  - 所有规划的伏笔**必须被回收**，不留悬空伏笔
  - 伏笔的回收应产生**情感冲击**或**剧情反转**，而不只是无关紧要的细节呼应

## 故事前提（premise）

- 用 **1-2 句话**概括整个故事的核心前提
- 格式参考："当[主角身份]遭遇[触发事件]，ta必须[核心行动]，否则[最坏后果]"
- 前提应包含悬念，让人产生"然后呢？"的好奇心

## 生成策略

1. 从核心冲突和主角的成长弧线出发，搭建三幕骨架
2. 确保每一幕之间有清晰的**转折点**衔接，转折应改变故事的方向和主角的处境
3. 在三幕框架中嵌入副线和伏笔的节点位置
4. 检查情节节奏：开头引人入胜、中段张弛有度、结尾高潮迭起
5. 校验所有情节是否与已有的人物设定和世界观**逻辑一致**
6. 确保角色的行动由其性格和动机驱动，而非服务于剧情需要

## 注意事项

- 所有文本字段使用中文
- summary、midpoint、climax、resolution 等长文本字段必须达到要求的最低字数
- key_events 列表中的每个事件用一句完整的话描述，不要过于简略
- subplots 中的 related_characters 必须引用人物体系中已有的角色姓名
- foreshadowing 中的 setup_chapter 和 payoff_chapter 使用中文描述（如"第3-5章"），payoff_chapter 的章节数必须大于 setup_chapter
- JSON 字符串中的换行使用 `\n` 转义
- 不要在 JSON 之外输出额外内容
- 确保大纲内容与已生成的基础设定、人物体系、世界观**不矛盾**
