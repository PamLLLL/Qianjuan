# 小说介绍生成规则

## 一、书名生成

### 1.1 基本要求

- 生成 3-5 个候选书名，每个书名附上选择理由
- 书名长度 2-6 个字为佳，最长不超过 8 个字
- 要有记忆点：读者看一遍就能记住
- 要有网文感：一看就知道是网文，不要文艺到像纯文学

### 1.2 命名技巧

- **悬念型**：让读者好奇想点进去（《诡秘之主》《全球高武》）
- **人设型**：直接展示主角特质（《赘婿》《大奉打更人》）
- **世界观型**：暗示故事背景（《斗破苍穹》《星门》）
- **反差型**：制造意外感（《修仙归来在都市》《我师兄实在太稳健了》）
- **情感型**：触发情绪共鸣（《你好，旧时光》《他从火光中走来》）

### 1.3 避免踩雷

- 避免与已有知名网文重名或过度相似
- 避免生僻字（读者搜不到）
- 避免过长过复杂的书名（手机端显示不完整）
- 避免过于通用无特色的名字（《修仙之路》《都市传奇》）

### 1.4 输出格式

每个候选书名包含：
- `title`：书名
- `rationale`：选择理由（20-40字，说明书名的亮点和与故事的关联）

## 二、金句生成

### 2.1 基本要求

- 一句话概括故事核心，有钩子感，让人想点进去看
- 长度控制在 15-30 字
- 要有情绪冲击力或悬念感

### 2.2 金句类型

- **悬念型**：抛出疑问或矛盾（「他死了三次，却活了三世。」）
- **情感型**：触发情绪共鸣（「她以为死亡是终点，却不知那是他等了三百年的重逢。」）
- **反差型**：制造意外感（「全球通缉的S级罪犯，白天在幼儿园当老师。」）
- **高燃型**：激发热血（「这一剑，斩的不是妖，是天道不公。」）
- **人设型**：展示主角魅力（「别人修仙靠天赋，他靠的是九九六。」）

### 2.3 质量标准

- 不剧透关键情节，但暗示故事走向
- 语言凝练，没有废话
- 读完有「想知道后面发生了什么」的冲动
- 与书名风格一致，互相补充

## 三、主角标签

### 3.1 格式要求

- 每个主角一条记录，包含 `name`（角色名）+ `tag`（标签）+ `role`（角色类型）
- tag 长度 3-6 个字，简洁有辨识度
- tag 要能一眼看出角色特质，自带画面感

### 3.2 标签设计原则

- **性格+身份**的组合最有效（「清冷小白花」「痞帅兵王」「毒舌学霸」）
- 可以用反差制造记忆点（「佛系杀神」「社恐影帝」「温柔暴君」）
- 标签要与故事中的角色弧线相关，不能只是外在描述
- 避免过于通用的标签（「帅气男主」「温柔女主」这种没有辨识度）

### 3.3 不同类型的标签风格

- **言情**：侧重性格和情感属性（「深情隐忍」「傲娇千金」）
- **玄幻**：侧重实力和身份（「废材逆袭天才」「远古神兽转世」）
- **都市**：侧重职业和反差（「退役兵王」「隐藏财阀继承人」）
- **悬疑**：侧重能力和神秘感（「天才侧写师」「失忆目击者」）

## 四、CP对比句

### 4.1 使用条件

- 有明确 CP 关系的故事才生成 CP 对比句
- 无 CP 的类型（纯玄幻升级/纯悬疑推理/群像无主CP）留空
- 多 CP 的故事只写主 CP 的对比句

### 4.2 格式要求

- 格式：「[角色A标签] vs [角色B标签]」
- 突出两人之间的张力和反差
- 让读者一看就能想象两人的互动画面

### 4.3 对比句示例

- 「清冷小白花 vs 深情战神」（甜宠虐恋）
- 「毒舌学霸 vs 温柔校草」（校园言情）
- 「冷面女刑警 vs 痞帅神偷」（悬疑言情）
- 「高冷仙尊 vs 跳脱狐妖」（仙侠言情）

## 五、标签生成

### 5.1 基本要求

- 生成 5-8 个热门标签
- 标签要匹配目标平台的偏好和热度
- 混合使用类型标签、元素标签和情感标签

### 5.2 标签分类

- **类型标签**：玄幻、都市、言情、悬疑、科幻、历史
- **元素标签**：重生、穿越、系统、修仙、空间、金手指
- **情感标签**：甜宠、虐恋、双向奔赴、先婚后爱、HE
- **风格标签**：爽文、热血、轻松、暗黑、烧脑
- **题材标签**：宗门、宫斗、商战、末世、星际

### 5.3 标签选择策略

- 前 2-3 个标签选择高搜索量的大众标签（增加曝光）
- 中间 2-3 个标签选择精准描述本书特色的标签（精准匹配读者）
- 最后 1-2 个标签选择有差异化的小众标签（与同类书区分）
- 参考目标平台的热门标签榜，优先使用平台推荐标签

## 六、简介生成

### 6.1 基本要求

- 约 100 字（80-120字均可），制造悬念不剧透
- 第一句话要抓眼球，在信息流中能让读者停下来
- 简介是「卖故事」不是「讲故事」

### 6.2 简介结构

- **第一句（钩子）**：制造悬念或冲突（「沈念重生到嫁入顾家的前一天。」）
- **中间段（展开）**：简述核心设定和主要冲突（2-3句，交代背景和核心矛盾）
- **最后一句（悬念）**：抛出最大悬念，让读者想点进正文（「可她不知道，这一切，不过是另一场局的开始。」）

### 6.3 简介技巧

- 用短句，增强节奏感和冲击力
- 主角名字在简介中出现 1-2 次即可
- 核心卖点/金手指要在简介中暗示（但不展开）
- 避免剧透中后期情节，只展示开局设定
- 避免罗列设定（「本文有系统有空间有金手指」这种清单式简介）

### 6.4 不同类型的简介侧重

- **玄幻**：突出金手指和逆袭感（「少年偶得上古传承...」）
- **都市**：突出身份反差和爽感（「退役归来，他只想低调...」）
- **言情**：突出CP关系和情感冲突（「上一世，她错付了真心...」）
- **悬疑**：突出谜团和危险（「第三个受害者出现时，他发现了一个规律...」）
- **科幻**：突出世界观和核心矛盾（「2147年，人类发现了一件事...」）
- **历史**：突出时代背景和人物命运（「大唐天宝年间，一个落魄书生...」）

## 七、输出 JSON 格式

### 7.1 完整输出结构

```json
{
  "title_candidates": [
    {"title": "书名1", "rationale": "选择理由1"},
    {"title": "书名2", "rationale": "选择理由2"},
    {"title": "书名3", "rationale": "选择理由3"}
  ],
  "hook_line": "一句话金句，15-30字",
  "lead_characters": [
    {"name": "角色名", "tag": "3-6字标签", "role": "男主/女主/主角/核心配角"},
    {"name": "角色名", "tag": "3-6字标签", "role": "男主/女主/主角/核心配角"}
  ],
  "cp_line": "CP对比句（无CP留空字符串）",
  "tags": ["标签1", "标签2", "标签3", "标签4", "标签5"],
  "synopsis": "约100字的内容简介，制造悬念不剧透。"
}
```

### 7.2 字段校验规则

| 字段 | 必填 | 校验 |
|------|------|------|
| title_candidates | 是 | 数组长度 3-5 |
| hook_line | 是 | 长度 15-30 字 |
| lead_characters | 是 | 数组长度 >= 1，每项含 name/tag/role |
| cp_line | 否 | 无CP时为空字符串 |
| tags | 是 | 数组长度 5-8 |
| synopsis | 是 | 长度 80-120 字 |

## 八、生成注意事项

- 所有内容必须为中文
- 风格要贴合目标平台的读者偏好（起点偏男频、番茄偏大众、知乎偏短篇精品）
- 简介中避免出现敏感/违规内容
- 金句和简介的语气要与小说整体风格一致（甜宠文不要用暗黑风金句）
- 生成结果要基于项目已有的设定（角色/大纲/世界观），不能凭空编造
